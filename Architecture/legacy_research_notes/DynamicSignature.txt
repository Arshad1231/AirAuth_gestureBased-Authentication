============================================================
                    AIRSIGN AUTH
       IN-AIR SIGNATURE BASED BIOMETRIC AUTHENTICATION
              DETAILED SYSTEM ARCHITECTURE
============================================================


1. PROJECT OVERVIEW
------------------------------------------------------------

AirSign Auth is a biometric authentication system in which a user
draws their personal signature in the air using their index finger.

A webcam captures the user's hand movement. MediaPipe detects the
hand and extracts hand landmarks. The index-finger movement is then
converted into a time-series trajectory.

The trajectory is processed to extract both:

1. Signature Shape
2. Signature Behavior

The system can analyze:

- X/Y/Z position
- Movement direction
- Velocity
- Acceleration
- Timing
- Trajectory length
- Direction changes
- Curvature
- Signature size
- Start position
- End position
- Temporal movement patterns

The trained machine-learning model then determines whether the new
signature belongs to the claimed user.

The system has two major pipelines:

REGISTRATION:
    Learn the user's signature pattern and create a profile.

AUTHENTICATION:
    Compare a newly captured signature against the registered
    user's signature profile.

============================================================
4. LAYER 1 - USER AND CAMERA INPUT
============================================================

Purpose:
    Capture the user's in-air signature.

The user stands or sits in front of a webcam and uses their index
finger to draw their personal signature in the air.

Flow:

USER
  |
  | Draw signature
  v
INDEX FINGER
  |
  v
WEBCAM
  |
  v
VIDEO FRAMES

The webcam continuously captures frames.

The frames are passed to the computer-vision pipeline.

Recommended setup:

- Laptop webcam is sufficient for the prototype.
- 720p or higher is preferred.
- Good lighting is recommended.
- Background should not be excessively cluttered.
- User's hand should remain inside the camera frame.

No special hardware is required for the initial prototype.


============================================================
5. LAYER 2 - COMPUTER VISION / HAND TRACKING
============================================================

Technology:

    OpenCV
    MediaPipe Hands

Purpose:

    Detect the user's hand and extract hand landmarks.

MediaPipe Hands provides approximately 21 landmarks for a detected
hand.

Important landmark:

    Index Finger Tip = Landmark 8

The first version of the system will primarily track the index
fingertip.

For every video frame:

    Frame 1 -> (x1, y1, z1)
    Frame 2 -> (x2, y2, z2)
    Frame 3 -> (x3, y3, z3)
    ...
    Frame N -> (xn, yn, zn)

Each point also has a timestamp.

Therefore, one signature becomes:

    [(x1,y1,z1,t1),
     (x2,y2,z2,t2),
     (x3,y3,z3,t3),
     ...
     (xn,yn,zn,tn)]

Future experiments can also use all 21 hand landmarks.

Possible experiments:

    Experiment A:
        Index fingertip only

    Experiment B:
        Full hand landmarks

    Experiment C:
        Index fingertip + temporal features

This allows the capstone to contain an ablation study.


============================================================
6. LAYER 3 - TRAJECTORY GENERATION
============================================================

Purpose:

    Convert finger movement into a digital representation of the
    air signature.

Every valid video frame generates a coordinate.

Example:

    TIME       X       Y       Z
    --------------------------------
    0.000     0.51    0.62    0.01
    0.033     0.52    0.61    0.01
    0.066     0.54    0.60    0.00
    0.099     0.57    0.58    0.00
    0.132     0.60    0.55    0.01

The system continues collecting points until the signature ends.

The recording can stop using:

- Keyboard key
- UI button
- Hand gesture
- Inactivity detection

One complete recording becomes one signature sample.

9. DATA COLLECTION PROTOCOL
============================================================

Each user should provide multiple genuine signatures.

Example:

USER U001

Session 1:
    10 signatures

Session 2:
    5 signatures

Session 3:
    5 signatures

Total:
    20 genuine signatures

Possible target:

    20-50 users
    20-30 signatures per user

The exact number depends on participant availability.

We should also collect impostor attempts.

Example:

User A registers their signature.

User B attempts User A's signature.

This becomes an impostor authentication sample.

Therefore:

GENUINE:
    User performs their own signature.

IMPOSTOR:
    Different user attempts authentication as the claimed user.

============================================================
11. PREPROCESSING LAYER
============================================================

Raw signatures will not always have the same number of points.

Example:

Signature A:
    180 points

Signature B:
    247 points

Signature C:
    205 points

The system therefore needs preprocessing.

Preprocessing operations may include:

1. Noise removal
2. Missing-point handling
3. Outlier removal
4. Coordinate normalization
5. Translation normalization
6. Scale normalization
7. Sequence resampling
8. Temporal normalization
9. Optional smoothing


11.1 Translation Normalization

The user may draw the same signature at different locations.

Example:

Signature 1:
    Starts at x = 0.30

Signature 2:
    Starts at x = 0.60

The shape can still be the same.

Therefore, coordinates can be normalized relative to a reference
point such as the starting point or centroid.


11.2 Scale Normalization

The user may draw a large signature during one attempt and a smaller
signature during another.

The system can normalize the bounding box or coordinate range.


11.3 Temporal Normalization

Different signatures may take different amounts of time.

Example:

Signature A:
    1.8 seconds

Signature B:
    2.7 seconds

Sequence models may require resampling or other sequence-handling
techniques.

    z

FEATURE GROUP 3 - VELOCITY

    movement direction
    angle

FEATURE GROUP 6 - CURVATURE

    trajectory curvature
    curve changes


FEATURE GROUP 7 - DISTANCE

    point-to-point distance

    width

FEATURE GROUP 9 - TEMPORAL FEATURES

    signature duration

    maximum speed
    pause duration
    speed variation


FEATURE GROUP 10 - BEHAVIORAL FEATURES

    direction-change frequency
    acceleration variation
    movement rhythm
    speed pattern


============================================================
13. FEATURE REPRESENTATION
============================================================

One trajectory point may become:

[x, y, z,
 vx, vy, vz,
 ax, ay, az,
 direction,
 curvature]

A complete signature becomes a sequence:

T1 -> Feature Vector
T2 -> Feature Vector
T3 -> Feature Vector
...
TN -> Feature Vector

This is important because an air signature is a TEMPORAL SEQUENCE.

Therefore, sequence models can be used.

14. MACHINE LEARNING LAYER
============================================================

The machine-learning pipeline should be developed progressively.

We should begin with classical baseline models and then move to
advanced sequence/metric-learning models.


------------------------------------------------------------
14.1 CLASSICAL BASELINE MODELS
------------------------------------------------------------

Possible models:

- Random Forest
- Support Vector Machine
- k-Nearest Neighbors

Purpose:

    Establish a baseline performance using engineered features.


------------------------------------------------------------
14.2 SEQUENCE MODELS
------------------------------------------------------------

Possible models:

- LSTM
- BiLSTM
- GRU

Input:

    Sequence of signature feature vectors

Output:

    User prediction or signature representation


------------------------------------------------------------
14.3 SIAMESE NETWORK
------------------------------------------------------------

A Siamese network can be investigated as the advanced authentication
architecture.

Instead of asking:

    "Which user is this?"

The system asks:

    "Does this signature belong to this user?"

Inputs:

    Signature A
    Signature B

Both signatures are passed through feature/embedding networks.

The network generates embeddings.

The embeddings are compared using a similarity/distance metric.

Example:

    Signature A
          |
          v
    Embedding A

    Signature B
          |
          v
    Embedding B

          |
          v

    Similarity / Distance
          |
          v

    Authentication Decision


============================================================
15. WHY SIAMESE NETWORK IS RELEVANT
============================================================

Authentication is fundamentally a verification problem.

Example:

Claimed User:
    U001

New Signature:
    Signature X

Stored User Signature:
    User U001 Profile

Question:

    Does Signature X belong to U001?

This is different from simply classifying signatures into user
categories.

A Siamese/metric-learning architecture can therefore be explored
for the final authentication system.

============================================================
18. AUTHENTICATION PIPELINE
============================================================

When a registered user attempts to log in:

STEP 1:
    User enters account/user ID.

STEP 2:
    Camera starts.

STEP 3:
    User draws their signature.

STEP 4:
    MediaPipe detects the hand.

STEP 5:
    Index fingertip trajectory is extracted.

STEP 6:
    Trajectory is preprocessed.

STEP 7:
    Features are extracted.

STEP 8:
    ML model generates prediction or embedding.

STEP 9:
    New signature is compared with the claimed user's profile.

STEP 10:
    Authentication score is calculated.

STEP 11:
    Score is compared with threshold.

STEP 12:

    If score >= threshold:

        ACCESS GRANTED

    Else:

        ACCESS DENIED


============================================================
19. AUTHENTICATION DECISION
============================================================

Example:

User:
    U001

Similarity Score:
    0.968

Threshold:
    0.850

Decision:

    0.968 >= 0.850

Result:

    ACCESS GRANTED


Another attempt:

Similarity Score:
    0.412

Threshold:
    0.850

Decision:

    0.412 < 0.850

Result:

    ACCESS DENIED

NOTE:

The values above are examples only.

The real threshold must be determined using validation data.


============================================================
20. AUTHENTICATION METRICS
============================================================

Accuracy alone is not sufficient for a biometric authentication
system.

The following metrics should be evaluated:

1. FAR
   False Acceptance Rate

   Measures how often an impostor is incorrectly accepted.


2. FRR
   False Rejection Rate

   Measures how often a genuine user is incorrectly rejected.


3. EER
   Equal Error Rate

   Point where FAR and FRR are approximately equal.


4. Precision


5. Recall


6. F1 Score


7. ROC-AUC


8. Authentication Latency


9. Genuine Acceptance Rate


10. Impostor Rejection Rate


============================================================
21. THRESHOLD SELECTION
============================================================

The ML model produces a score.

The system defines a threshold T.

If:

    score >= T

Then:

    ACCEPT

Otherwise:

    REJECT

The threshold should be selected using validation data rather than
choosing an arbitrary value.

Example:

Threshold     FAR       FRR
--------------------------------
0.60          ...
0.70          ...
0.80          ...
0.85          ...
0.90          ...
0.95          ...

The final threshold should balance security and usability according
to the project's evaluation criteria.

============================================================
34. SECURITY CONSIDERATIONS
============================================================

Because this is a biometric authentication system, security must be
considered from the beginning.

Important considerations:

1. Do not store passwords in plain text.

2. Protect database access.

3. Protect stored biometric information.

4. Do not expose raw biometric data unnecessarily.

5. Authenticate API requests.

6. Record authentication attempts.

7. Version the ML model.

8. Add rate limiting.

9. Avoid real banking information.

10. Investigate replay attacks.


============================================================
35. ADVANCED SECURITY FEATURES
============================================================

After the core system is working, the following features can be
investigated:

A. LIVENESS DETECTION

Determine whether the signature is being performed live.


B. 3D TRAJECTORY

Use MediaPipe depth information.


C. DYNAMIC BEHAVIOR

Use:

    Speed
    Timing
    Acceleration
    Movement rhythm


D. CHALLENGE-RESPONSE SIGNING

Instead of asking for the exact same signature every time, the
system could ask the user to draw a dynamically generated pattern.


E. MULTI-FACTOR AUTHENTICATION

Example:

    Account ID
        +
    Air Signature
        +
    Optional PIN / OTP


F. ANTI-REPLAY DETECTION

Detect whether the captured movement is a replayed or previously
recorded pattern.


These are advanced/future modules and are not required for the
first working prototype.
